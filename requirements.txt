# Post-deliverable validation (gc_validation.deliverable, the cell-74 trigger).
# It resolves the run's brand config through `gc_core.config.loader`, which parses
# configs/brands/*.yaml into the `BrandConfig` pydantic model and reshapes it back
# with `to_legacy_dict()`. gc-core declares pydantic only under its `config` EXTRA,
# so nothing pulled it into this env transitively and the import failed at run time.
#
# The consequence was not a skipped check but five wrong ones: `resolve_context()`
# raises on that import, and it is the single call that derives
# ELASTICITY_RECON_ANCHOR_BRAND / _CACHE_DIR / _CATEGORY / _TIER. A1 then reconciled
# every pooled SKU (competitors included) against an own-brand-only dashboard table
# and reported `0/N matched` as a VETO fail; A4 looked for the comp-set CSV under the
# module's Zydus_Sugarfree default; A2/B1 never ran. Every in-run validation scored
# ~5% FAIL on deliverables that were fine -- verified on GLENMARK, whose elasticities
# are byte-identical to a manually-validated copy that scored 43%.
#
# Same pin as requirements-lock.txt (and already installed in the ds-pipelines image,
# which is why the libs pipeline was never affected) -- keep the two in step.
pydantic==2.13.4

# LLM band resolver (gc_validation.deliverable.llm_bands -> gc_core.llm.gateway).
# Picks the category/tier reference band per brand at validation time.
#
# `gc_core.llm.gateway` imports this LAZILY and by design -- importing the module
# must work without the SDK. Lazy defers WHEN the ImportError lands, not WHETHER:
# the call site still executes `from claude_agent_sdk import ...`, so with the SDK
# absent every run resolved `category=(none) tier=(none)` and check C2 judged every
# brand against the F&B default [-3.5, -0.2] -- right for a laddoo brand, wrong for
# pharma or electronics. Visible in the report as
# "LLM call failed (ModuleNotFoundError: No module named 'claude_agent_sdk')"
# (LALSWEETS, 2026-08-12).
#
# NOT SUFFICIENT ON ITS OWN: this SDK is a client for the Claude Code CLI (hence
# the gateway's `CLINotFoundError` handling), so the image also needs Node + the
# CLI -- see dags/Dockerfile.template. Pinned to the version this repo runs
# against locally, not `latest`: the resolver's output selects the band a client
# deliverable is judged by, so it moves deliberately.
claude-agent-sdk==0.2.135
